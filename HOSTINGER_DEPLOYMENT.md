# ChargeReady configuration and remaining launch work

GitHub source upload is authorized. Domain deployment is pending the domain, hosting details and launch requirements below. See `deploy/README.md` for Linux VPS, HTTPS and owner-admin setup templates. Packaging scripts never deploy automatically.

Implemented locally: per-application access, encrypted revision storage, session revocation, optimistic conflicts, email verification/reset adapters, recovery-key design, administrator TOTP MFA and reauthentication, private support, provider order/capture/webhook adapters, policy drafts, tests and source packaging.

Still owner-dependent before public launch:

1. Supply business identity, support email/contact, approved refund terms, lawful retention periods and applicable jurisdictions. Obtain qualified immigration-content, privacy/legal and independent security review. Do not set `LEGAL_REVIEW_APPROVED=yes` until this is actually done.
2. Provision a supported private database volume/managed service and a reverse proxy with HTTPS and configured `VISA_ORIGIN`. The current SQLite implementation supports a single instance; a managed Postgres migration is separate hosting work. The app binds to localhost. Install Poppler (`pdftoppm`) for actual PDF page previews; if absent the app explicitly offers the structured review and PDF download. Set proxy body/time/rate limits and a safe restart/monitoring strategy.
3. Set `VISA_SECRET_KEY` from a private secret manager and preserve it separately from the encrypted database backup. Do not share it. MFA secrets are encrypted under this key. Never rely on the local generated secret file as your only production backup.
4. Configure a real transactional SMTP service, verify sender identity/delivery, and test reset/verification mail. Local mail-preview files must never be exposed publicly. Validate recovery-code loss, MFA recovery and abuse handling with real operational procedures.
5. Connect the operator's eligible PayPal Business integration using sandbox credentials first. Configure Orders v2, merchant ID, webhook ID and the HTTPS webhook endpoint `/api/payments/webhook`. Subscribe to capture completed/denied/refunded and dispute-created events. Test real sandbox approval, capture, duplicated/out-of-order callbacks, partial refunds and disputes. The implementation revokes access on any mapped refund; confirm the approved product policy. No provider certification or live-payment testing has been performed.
6. Configure `OPENAI_API_KEY` and `OPENAI_MODEL` only if offering live AI editing. Test model behavior/costs and provider retention disclosures. The service never supplies its API key to the browser. Do not sell unconfigured AI features as active.
7. Enroll administrator MFA and remove public test accounts/passwords before launch. Do not change a customer's password without understanding encryption recovery. Owner-only local administrator reset is provided by `admin_setup.py`.
8. Set an encrypted database backup schedule with separately held `VISA_BACKUP_KEY`, test a restore into a new location, define rotation/deletion and protect access logs. New audit entries have an HMAC chain for detecting modified signed entries; historical unsigned events are labeled. Audit records are append-only through the app API, but a database administrator can change the database and external anchoring is needed to detect complete trailing history removal; independent log integrity/storage is infrastructure work.
9. If a trusted reverse proxy sets `X-Real-IP`, configure `TRUSTED_PROXY_IPS` to its exact source IPs. Do not trust forwarded client headers from arbitrary senders. Only hashed subjects are stored for request limiting. Geographic analytics are deliberately not enabled without a provider and disclosure.
10. Run the full test suite in a clean environment, inspect 2–3 page print output and test phone/keyboard/accessibility flows. Full accessibility certification, multilingual shaping and automatic legal worksheet matching are not claimed.

Official PayPal references: https://developer.paypal.com/api/rest/integration/orders-api and https://developer.paypal.com/api/rest/webhooks/rest/
